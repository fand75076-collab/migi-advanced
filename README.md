# Migi Advanced

Migi Advanced 是独立于 Codex 内置宠物引擎的 macOS 原生透明浮层；现有内置 Migi
v3.3 仍可作为回退。v0.13 使用完整角色关键帧与 8 × 21 图集：Migi 始终以右手腕
基线为身体锚点，眼柄、触手、手指和器官形态在每帧中作为连续的完整原画重建。
Metal 仅为允许的软组织区域施加局部弹性形变，并保护电脑、手机、书本和眼眶等
刚性区域；它不把角色拆成可任意拼装的部件。

v0.15.0 改善动作的连续性与眼部表现。工作速率通过连续积分时钟在约 0.2 秒
内缓动，不再用新速度重算整个片段的历史进度；呼吸独立累计相位，能量变化
不会被系统开机时长放大，身体下沿保持锚定，电脑和书本不再整体上下漂移。
眨眼改成不透明上下眼睑的真实闭合，逐眼错峰也分别完成闭合和张开；眼神用
解析临界阻尼保持不同刷新率下的一致响应。眨眼、分支眼追赶与状态交接保持
60 FPS，降档等待 0.55 秒稳定期，深睡仍降到 15 FPS。交接时程序眼的透明度
跟随所在组织的出现进度。原有 29 个动作、原画与行为优先级继续保留。

修改前后同输入的 GPU 动画对照、时钟回归检查和复现命令见
[`QA/motion-quality-v0.15.0/README.md`](QA/motion-quality-v0.15.0/README.md)。

v0.14.3 观影礼貌退场：当其他进程以前台全屏窗口覆盖宠物所在屏幕（原生全屏
Spaces 的 QuickTime/TV/IINA、无边框全屏的 mpv `--fs` 与网页播放器）或屏幕
进入锁定/登录界面时，`MigiScreenGuard` 以 2 Hz 低频轮询检测并把宠物面板与
对话气泡一并收走，播放或锁屏结束后自动回到原位。判定只依赖窗口几何
（前台应用 PID + layer 0 + 覆盖率 ≥92%，普通最大化窗口到不了该阈值），不
读窗口标题、不截图、不做进程名硬编码；状态循环演示与全部 QA 路径豁免，保持
既有验收的确定性。两个浮层面板不再携带 `fullScreenAuxiliary`，原生全屏空间
里不再出现宠物残影。

警戒环顾到伏案工作的最后 0.42 秒使用单体轮廓匹配过渡：任何时刻只绘制一套

v0.9.0 重绘最常驻的六组动作并重做播放时间轴：待机、电脑、手机和双书阅读均为

v0.11 加入克制的非语言交互：短按可见身体时，锚定待机的 Migi 只环顾一次；
电脑、阅读、等待、审阅和普通失败保持原动作与道具，仅让眼神短暂集中。离体侦察

v0.12.0 接入本地 Agent 的对话气泡：复用已有的会话日志尾随，把三个 Agent 在本机

v0.13.0 新增三段多 Agent 生物式过渡，不使用光环、粒子、品牌色或独立克隆：

- 从单 Agent 进入并行时，右手腕形态先完整执行 2.94 秒“主眼确认 → 多眼柄异步

- 并行集合不变而主控 Agent 切换时，先保留原朝向完成 1.40 秒环顾，再以独立

- 从多 Agent 回到单 Agent 时，以 1.48 秒一二三触指计数收束；若两个实时来源同时结束，
  直接吸收未完成的交接，不会再朝离线来源误转。

显式读取、写入和新工具动作会先完整播放；等待与失败仍立即抢占。交接有 3 秒
防抖，同帧来源回切会先更新最新目标再决定是否转身；ZCode 仍只是完成后感知，不伪造实时交接。

- Grok：`~/.grok/sessions/*/updates.jsonl`，从 `agent_message_chunk` 的
  `update.content.text` 累积流式回复文本。
- Codex：`~/.codex/sessions/**/rollout-*.jsonl`，从 `agent_message` 的
  `payload.message`、assistant `response_item` 的 `payload.content[].output_text`，以及

- ZCode：`~/.zcode/cli/rollout/*.jsonl`，从 `model_io` 记录的 `response.text`

文本以 4096 字符尾部有界缓冲存入 `CodexActivitySnapshot.spokenText`，并带独立的
`spokenAgent` 与 `spokenRevision`。新增 `MigiSpeechBubbleController`——
独立的非激活浮层（NSVisualEffectView popover 材质、圆角、淡入淡出），与 sprite 浮层
平级，跟随宠物位置且鼠标穿透；不触碰 Metal 渲染与行为状态机。回复与动画状态独立
仲裁，因此 Agent 在同一次轮询中写入最终回复并立即完成时仍会显示，长任务也按末次

关闭会立即清空浮层，重新开启不会回放旧回复。

## 当前架构与行为

- 每只可见眼通过独立阻尼弹簧在固定眼眶内缓慢跟随鼠标；一只眼柄在巡游或转身
  中收回时，其余眼睛仍连续追踪，眼柄和身体不会被鼠标拉向一侧。
- 短按和拖动以 4 pt 位移阈值分流；短按仅命中保守的可见角色包络，不把透明浮层
  四角当作 Migi。悬停需持续 300 毫秒，并在离开后用约 200 毫秒平滑恢复普通眼神。
- 用户互动是低频的“注意信号”，不替代工作语义、不充当批准；v0.12 新增对话
  气泡复述当前感知来源 Agent（Codex / Grok / ZCode，或全部）已有的回复——仍不
  联网、不主动生成，仅把本机会话日志里已记录的回复文本以气泡形式显示。休眠、
  梦境、渐醒与可信安全威胁始终优先。v0.13 之后的原作化补充：
  - 持续注视身体≥3 秒会得到一次“回视”：原地完整转身面向着你、双眼汇聚
    4.5 秒；巡游、睡眠、渐醒、工作姿态与可信威胁下不回回视,冷却 20 秒。
  - 拖动浮层超过阈值后，全体眼睛汇聚于光标、瞳孔微缩 15%、组织形变降一档
    ——被拿住时它容忍，但它看着你。
  - 保护盾持续随关系阶段增长:cautious 0.7s / cooperative 0.9s / protective 1.2s;
    关系越深,防御越接近本能反射。
  - 四小时睡眠债:高强度协作按 8 小时满债累积,待机/等待低耗累积,完整深
    睡以 5× 速率清偿;疲劳压低整体能量上限(×0.7 起)、显著削减闲置小动作,
    入睡阈值从 30 分钟缩到 9 分钟,最小深睡从 20 秒延长到 60 秒。账本持久化在
    `~/.codex/migi-advanced/sleep-v1.json`,关机/退出 6 小时清零。
  - Migi 低语:入睡、可信威胁护盾、首次进阶 protective 三条本地硬编码冷
    静短句,借用气泡层、各自冷却或仅此一次;状态栏“Migi 低语”可关。
  - 阅读姿态的眼睛不跟风指针:分支眼以每行 1.9s 逐行扫读,行末一瞬回扫,
    分支眼之间错相;主眼仍留给指针。
  - 稳定长姿态超过 8 秒后允许一次慢眨,间隔 26-48 秒;睡眠与渐醒阶段仍然
    完全不眨眼。
  - 深睡呼吸改为非正弦双波形(急吸慢呼),幅值仍限在原作剪影内。
  - 打字手指、速记与工作态翻页的节奏跟随日志真实产出速率(0.75x–1.4x 对数
    映射):日志沉默时笔画放慢,喷发时加速;纯演示与 QA 永远保持原速。
- 所有形态都从同一右手腕基线和连续的有机根部重建；待机、左右巡游和转身使用
  完整角色逐帧原画。左右巡游是两套独立八帧素材，离体巡游只是短程、低频的侦察
  与回归，绝非 Migi 的常态拓扑；任何非待机语义都会立即使其回到右手腕锚点。
- 身体采用区域权重软组织形变，刚性道具和眼眶不扭曲；眨眼、打字手指、点按手机、
  双书阅读、翻页、掌中观察和器官游走均由对应片段驱动。
- Codex 思考稳定显示电脑；读取/搜索显示双书阅读；明确应用补丁、编辑或写入
  使用多触手精细操作；无法分类的新工具短促取样；等待用户时看手机；审阅与整理
  使用信号取样。普通失败只进入 `calm-diagnosis`（平静诊断）；只有监测器明确判为
  `credibleThreat` 的安全威胁，才按“保护盾 → 刃尖硬化”呈现。
- 可选感知 Grok Build 与 ZCode；每种来源使用独立事件适配器和状态时效，
  “全部 Agent”模式才会进行跨来源仲裁，升级后默认仍是 Codex。
- 待机 8–16 秒内会出现第一次低频原作式小动作，之后每 18–34 秒在自然停稳时从
  看书、看手机、掌中观察、信号取样、流态伸展、短暂休眠、速记、精细协调、器官
  游走、冷静计数、收纳和恢复照护中选择；动作有独立冷却，且不连续播放同一族。
- 关系阶段为 `cautious`、`cooperative`、`protective`：由实际前台协作时长与熟悉
  工具数共同累计，不能靠应用闲置升级，并只做缓慢的闲置权重与恢复照护调整。
- 连续空闲 30 分钟后进入完整睡眠：强制隐藏所有共生器官眼睛、停止巡游和鼠标
  追踪，只保留极弱生命起伏；
  恢复活动时先经历约 1.2 秒梦境扰动，再警戒环顾约 1.6 秒；梦中冻结凝视，
  环顾时恢复眼神活动；最后以约 0.42 秒的单体轮廓匹配过渡进入真实工作姿态，
  同时菜单状态立即显示真实任务状态。
- 每个 Agent 首次出现无法归为读取或写入的新工具时，Migi 会短促检视两轮；
  同一 Agent 不重复，已知读取和写入工具继续使用各自的原作式语义动作。
- “全部 Agent”模式按 Codex 与 Grok 两类真实实时来源去重统计活跃信号，
  不会把同一 Agent 的多个任务日志误算成多人协作。单→多、主控来源切换、多→单
  分别使用完整多眼柄采样、环顾—原地转身、触指计数三段动作；明确的读取、写入和
  新工具动作优先完整播放，等待与失败仍可立即抢占。
- 做完整组织变形时右手腕根部保持基线锚定；动画按根到梢错相，而不是整张图同步
  扭动。
- 工作状态收到待机信号后保持至少 20 秒，等待用户和失败状态可立即抢占。
- Metal 在快速巡游、失败反应、拖动、眼睛追赶和九组高细节新动作时保持
  60 FPS，稳定动作使用 30 FPS，深眠使用 15 FPS；贴图分辨率和程序化眼睛
  精度不降低。三个顶点缓冲
  具有独立 GPU 所有权，GPU 忙时跳过单个视觉帧而不会覆写仍在使用的缓冲。
- 位置和尺寸会记住；升级到 v0.5.1 时旧尺寸会一次性迁移为 115 × 135 小号，
  并保持原窗口中心点和底边位置。
- 状态栏 `◉` 菜单可复位、改尺寸、循环演示、开关 Agent 回复气泡、选择性开启异常
  通知和退出。
- “登录时启动”使用 macOS 13+ 的 `SMAppService`，仅在用户主动勾选后注册。

## Codex 状态映射

| Codex 状态 | Migi 表现 |
| --- | --- |
| thinking / reasoning | 电脑与连续打字动画;回复文本正在流式输出时改为速记(代笔转述) |
| read / search tool | 本地读取与搜索为双书并行阅读;web/fetch 远端观察为掌中观察 |
| apply / edit / write tool | 多触手精细操作 |
| shell 执行 | 输出回流期间持续速记;其中测试/验证命令先播一次完整一二三计数 |
| context_compacted | 一次完整收纳(45s 冷却),随后回到协调姿态 |
| sub_agent_activity | 一次手腕锚定的离体侦察—回归(60s 冷却),随后回到协调姿态 |
| unknown tool / shell | 首次信号取样两轮;同一 Agent 不重复 |
| waiting / approval | 手机;连续等待超过 90 秒放下手机、自检手指 |
| review / task complete | 信号取样与对照核验;持续 ≥60s 的轮次结束回待机时组织舒展一次(180s 冷却) |
| failed / interrupted（普通） | 平静诊断，随后按关系阶段可有恢复照护 |
| failed / interrupted（明确可信安全威胁） | 保护盾短暂拦截，随后刃尖硬化 |
| idle | 右手腕锚定的待机、眨眼、低频短程离体侦察—回归、原作式小动作与完整睡眠 |

状态桥按用户选择只读尾随：

- Codex：`~/.codex/sessions/**/rollout-*.jsonl`
- Grok Build：`~/.grok/sessions/**/updates.jsonl`
- ZCode：`~/.zcode/cli/rollout/**/model-io-*.jsonl`

应用不修改任何 Agent 配置，不安装 hook，不联网，也不向日志写入内容。现有候选
文件每 0.8 秒刷新轻量元数据，新会话低频发现；一次新增内容超过 1 MiB 时会分块
追赶，并保留当前任务与工具状态；异常的单条超长记录超过 4 MiB 时只丢弃该记录，
不会清空当前任务。跨来源事件先锚定到最新时间簇，再按状态优先级确定性仲裁。
Grok 的 ACP 更新可以流式感知；ZCode 的
`model-io` 记录在响应完成后才落盘，因此 ZCode 当前提供完成后感知，不伪造实时
开始状态。

## 构建、测试与安装

要求：macOS 13 或更高版本、Metal、Swift 6 工具链。当前本机构建为 Apple Silicon。

```zsh
swift test --package-path migi-advanced
migi-advanced/scripts/install-app.sh
```

安装位置：

```text
~/Applications/Migi Advanced.app
```

安装脚本默认重新构建，避免源码已更新却安装旧包。若已明确构建过，可使用
`install-app.sh --no-build`。`install-and-launch.sh` 会安装后通过后台 CUA 启动，
不会抢走当前应用焦点。

旧版本会以 `.app.backup` 保存到：

```text
~/Library/Application Support/Migi Advanced/Backups/
```

构建产物的旧版本保存在工程内 `backups/dist/`。这些备份不再使用 `.app` 结尾，
避免 LaunchServices 按同一 bundle ID 启动到旧副本。

## 使用

- 在 Migi 可见身体上短按会得到一次克制回应；8 秒内的重复短按不会反复表演。
- 拖动超过 4 pt 后才移动浮层，可调整位置；拖回原点仍按拖动处理，不误触发回应。
- 点击菜单栏 `◉`：
  - 查看当前 Agent 与活动状态；
  - 在“感知来源”中选择 Codex、Grok、ZCode 或全部 Agent；
  - 开关状态循环演示；
  - 开关“Migi 低语（关键状态）”（默认开启）；
  - 选择性开启“异常时通知”（默认关闭，首次开启会请求系统权限）；
  - 开关登录时启动；
  - 回到屏幕右下区域；
  - 选择小、中、大尺寸；
  - 退出。
- 第一次启用“登录时启动”若显示“需系统批准”，请在 macOS“系统设置 → 通用 →
  登录项与扩展”中批准。

## 开发验收入口

固定状态和 Metal 透明帧导出用于可重复视觉 QA，不影响正常启动：

```zsh
/Applications/Migi\ Advanced.app/Contents/MacOS/MigiAdvanced \
  --demo-state=tool \
  --qa-capture=/tmp/migi-tool.png \
  --qa-capture-delay=1 \
  --qa-exit-after=8
```

`--demo-state` 支持 `idle`、`thinking`、`tool`、`waiting`、`review`、`failed`。
`--demo` 则从启动时刻开始，每 8 秒循环一个状态。

多 Agent 过渡可用 `--qa-agent-transition=join`、`handoff` 或 `leave`
确定性触发。演示会先稳定在初始工作姿势 0.20 秒，再投递对应的真实快照变化，
用于验收完整时钟、方向和收束。

渐醒阶段可用 `--qa-wake-phase=deepSleep`、`dreamDisturbance`、`lookAround`
或 `awake` 固定起始点。`deepSleep` 保持休眠，其余渐醒阶段按真实时序继续演进，
便于采样完整渐醒动画。

眼神方向可用只供 QA 的 `--qa-gaze=x,y` 固定，例如 `--qa-gaze=-1,0` 与
`--qa-gaze=1,0`；正常启动始终读取真实鼠标位置。

v0.11 的交互捕获可加 `--qa-tap`（或 `--qa-interaction=tap`）触发一次短按，
也可用 `--qa-hover=on` / `off` 固定悬停注意层；这些参数只用于确定性 QA。
过渡时序验收可用 `--qa-demo-state-duration=0.5` 缩短 `--demo` 的单状态
停留时间（范围 0.25–8 秒），无需等待默认八秒周期。

角色方向可用 `--qa-facing=left` 或 `--qa-facing=right` 固定；它只影响 QA
进程，用于核对左右巡游和带道具姿态，不改变正常启动的随机初始朝向与巡游逻辑。

带 `--qa-capture=` 的 LaunchServices 启动使用独立 QA 锁，因此可在不唤醒或
替换正常桌面宠物的情况下短暂导出 Metal 帧；`--qa-exit-after=` 会在 1–30 秒
范围内自动退出该捕获实例。未带 QA 参数的桌面入口仍严格保持单实例。

任一图集动作都可用 `--qa-clip=<片段名>` 强制显示。v0.10 新增或重建的片段为
`normal-hand`、`palm-observer`、`signal-sampling`、`storage-pocket`、
`recovery-care`、`calm-diagnosis`、`detached-scout-return`、
`complete-sleep`、`complete-sleep-wake` 和 `protective-shield`；连同既有
左右巡游、独立转身、设备交互、阅读、精细操作及变刀动作，清单共 29 项。
